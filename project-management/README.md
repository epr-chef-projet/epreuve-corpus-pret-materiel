# Références du projet

Ce dossier regroupe la documentation et les supports de gestion du projet selon le [guide Documentation et partage](docs/procedures/documentation-et-partage.md#2-organiser-les-références-et-les-points-dentrée). Les références partagées se trouvent dans `docs/` ; les documents locaux privés dans `local/`. Le [README racine](../README.md) présente l'application et son état fonctionnel.

| Besoin                                 | Référence                                                                                                                           |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| Comprendre le produit et sa conception | [Documentation et cahiers des charges](docs/README.md)                                                                              |
| Installer et utiliser sa copie         | [Installation](docs/interne/developpement/installation.md) et [environnement](docs/interne/developpement/environnement.md)          |
| Comprendre les échanges entre modules  | [Contrats](docs/interne/architecture/contrats-et-lots.md)                                                                           |
| Tester et proposer une contribution    | [Qualité](docs/interne/developpement/qualite-et-recette.md) et [contribution](docs/interne/exploitation/collaboration-livraison.md) |
| Entretenir la documentation            | [Procédure interne](docs/interne/developpement/contribution-documentation.md) et [guides](docs/procedures/README.md)                |
| Sélectionner les règles                | [Profil technique](docs/interne/profil-projet.md) et [index du corpus](../.ai/rules/index.md)                                       |

Les documents partagés décrivent l'état et les contraintes actuels du projet. Les journaux de bord, plans personnels, notes de reprise et conversations restent privés. Le sous-dossier `local/` est prévu pour ce suivi personnel : il est ignoré par Git et exclu des images et archives distribuées. Il n'est pas nécessaire à l'utilisation d'un clone.
